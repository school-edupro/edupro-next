# UAT script for Phase 2 (admissions, academics, attendance, communication)

For the pilot school's super-users. Each scenario names the login from `docs/demo-logins.md`, the steps and the
expected result. Record pass/fail and remarks in the last two columns. The pilot has not yet run this script:
the M2 gate condition stays open until they do.

| #   | Area          | Login                                  | Steps                                                                               | Expected                                                                         | Result | Remarks |
| --- | ------------- | -------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ------ | ------- |
| 1   | Admissions    | public app                             | Open the school page, apply for Class I with a new mobile, complete the OTP, submit | Application number shown; status page lists it                                   |        |         |
| 2   | Admissions    | `dev-admin`                            | Cycle → Decisions: shortlist, draw of lots with a seed, send for approval           | Requests appear at level 1                                                       |        |         |
| 3   | Admissions    | `dev-coordinator` then `dev-principal` | Approve in **My inbox** at both levels                                              | Application selected; offer with fee visible to the applicant                    |        |         |
| 4   | Admissions    | public app                             | Pay the admission fee on the status page (development gateway)                      | Badge turns to Fee paid                                                          |        |         |
| 5   | Admissions    | `dev-admin`                            | Admit the selected application                                                      | Admission number, student record, guardian, enrolment in the coming year         |        |         |
| 6   | Academics     | `dev-admin`                            | Assign a subject teacher; set a timetable slot that clashes                         | Role and scope appear; clash refused                                             |        |         |
| 7   | Academics     | `dev-teacher`                          | Post homework with a PDF; write a weekly lesson plan and submit                     | Homework in the parent app; plan awaiting approval                               |        |         |
| 8   | Academics     | `dev-coordinator`, `dev-admin`         | Approve the plan at levels 1 to 3 (Vice Principal by designation at level 2)        | Plan approved; teacher sees the decision                                         |        |         |
| 9   | Academics     | `dev-coordinator`                      | Arrange a substitution for an absent teacher                                        | Free teachers listed lightest-load first; conflict refused; teacher app shows it |        |         |
| 10  | Attendance    | `dev-teacher`                          | Mark today's attendance with two absents; try a Sunday                              | Alerts sent once; Sunday refused                                                 |        |         |
| 11  | Attendance    | device                                 | Post gate and bus taps with the demo keys; repeat one within a minute               | present/late/boarded; duplicate flagged; dashboard counts move                   |        |         |
| 12  | Attendance    | `dev-coordinator`                      | Set a per-student rule (late 08:00, mute alerts); lock a register                   | Override applied on the next tap; teacher cannot edit a locked register          |        |         |
| 13  | Communication | `dev-coordinator`                      | Compose a circular to two sections, preview recipients, send for approval           | Skips explained (no mobile, consent withdrawn); request awaits the principal     |        |         |
| 14  | Communication | `dev-principal`                        | Approve the circular; open the request                                              | Messages queued per recipient; delivery counts on the request                    |        |         |
| 15  | Communication | `dev-parent`                           | Withdraw WhatsApp consent, then check a new general circular's recipient list       | The parent is skipped with "consent withdrawn"; service messages still arrive    |        |         |
| 16  | Engagement    | `dev-parent`                           | Raise a query and a leave request; reply; rate after the answer                     | Teacher sees them; leave closes with a decision; rating recorded                 |        |         |
| 17  | Engagement    | `dev-parent`                           | Request a mobile number change; `dev-admin` approves                                | Guardian record updated; audit row                                               |        |         |
| 18  | Privacy       | `dev-parent`                           | Sign in after a new privacy notice is published                                     | Onboarding page appears once; consents captured; not asked again                 |        |         |
| 19  | Compatibility | current teacher app                    | Post homework, attendance and a notice through the legacy endpoints                 | Same rules as the new apps; legacy envelope answered                             |        |         |
| 20  | Offline       | parent app                             | Install the PWA, open it in airplane mode                                           | Last seen pages or the offline page, never a browser error                       |        |         |
