## 4. Decisions

- The workflow engine is generic (entity type + id + payload) but Sprint 9 wires only admissions; leave and purchase approvals reuse it later. Completion handlers run inside the final step's transaction so a decision and its consequence commit together.
- Payment intents are the source of truth; the gateway is untrusted. Every notification is recorded (`payment_webhooks`) before it is judged, so replays and forgeries leave an audit trail without side effects. The mock gateway exercises the same verification code as production.
- Admission numbers are issued at admission (not at selection) from a per-school row-locked sequence, mirroring the legacy `Admission` register; the application keeps a link to the student.
- Attendance keeps one row per student per session with the source (`manual` or `rfid`) and the reader never overrides a teacher's mark; a teacher can override the reader. Alerts are sent through the existing messaging outbox so they follow the same consent, template and delivery rules.
- Real PayU credentials and a merchant account are the user's to provide; `PAYU_MODE=test` switches the form target to PayU's test URL without code changes.
