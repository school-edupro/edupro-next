## 4. Decisions

- **One procedure for every receipt.** Cash, cheque and gateway successes post through `app.post_receipt`, so numbering, allocation, late fee and audit cannot diverge between the counter and the gateway.
- **Late fee is posted beside the computed figure.** The ledger shows computed, posted and outstanding; `payable` is the balance plus the outstanding late fee. Nothing is charged silently and nothing is waived silently (a waiver stays an override).
- **Rejected notifications do not consume the idempotency key.** The e2e found that a forged notification answered first made the genuine one a `duplicate`; the fix is in `applyNotification` and documented as P11 in the threat model.
- **Refunds reverse newest first** so the oldest dues stay settled; demands reopen instead of a negative receipt.
- **Departments open by module permission**, not a second permission tree.
- **Settlement files never create money**: a line only matches an existing succeeded intent.

## 6. What the tests found before release

- **A forged notification blocked the genuine one.** The first e2e run answered a bad-signature Razorpay return first; the genuine return that followed was `duplicate` because the (provider, reference, status) key had been consumed. Rejected notifications now get a unique key (threat model P11).
- **`/payments/offline` must stay principal-only.** Routing the Sprint 9 endpoint through `app.post_receipt` with late fee collection broke 32 of the 200 harness cases whose legacy model allocates the whole amount to principal. The endpoint keeps its meaning (allocation only; the late fee stays outstanding for the cashier), and the cashier endpoint collects the late fee.
- **Numeric zero renders as `0`** from `numeric::text`; the service formats every money field.
- **Provider references are global** (`payment_webhooks`, `payment_intents.provider_ref`), so the spec builds them from the run stamp like school codes.
- **The print-receipt redirect** on the cashier page built `?studentId=…?ok=1`; found in the browser walk-through and fixed.

Known gaps carried forward: family receipt PDFs, PayU and CCAvenue refunds through the provider API, CCAvenue server callback, real gateway credentials never exercised, Hindi for the detailed parent pages, historical ETL loader run (dumps), credit larger than its instalment not carried forward (Sprint 12).
