## Decisions taken in the sprint

1. **Locale by cookie, not by URL.** The admin app is behind sign-in and the school context already travels in cookies; a locale segment would double every route. `next-intl` reads the cookie in `i18n/request.ts`.
2. **Trigram search instead of full text.** `search_text` generated columns (lower-cased, unaccented) with GIN trigram indexes serve prefix, word-start and similarity queries in one function; exact admission numbers, employee codes and mobiles rank first.
3. **Students never get a login from the migration.** Their identity is `legacy:<school>:<table>:<key>` until the school decides on student logins (playbook section 3); guardians are keyed by mobile.
4. **Compatibility sessions are HS256 tokens with the `compat.` prefix**, verified by the same guard as One Auth tokens; the school id inside the token replaces the `X-School-Id` header the current apps cannot send. `app.compat_lookup` is the recorded SECURITY DEFINER exception for the pre-context lookup.
5. **ID cards reuse the export pipeline.** A renderer registry sits beside the dataset registry; the worker renders the HTML card through Chromium at CR80 size and registers the file like any export.
6. **ETL lookups name the school explicitly** in addition to row-level security, because the migrator connection used in tests bypasses policies.
