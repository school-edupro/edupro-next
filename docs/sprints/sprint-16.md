## 2. Data model and permissions

- Migration `0027_sprint16_shadow_results_ai_reports.sql`: `service_keys` + `app.service_key_lookup`;
  `shadow_feeds`, `shadow_legacy_receipts`, `shadow_legacy_balances`, `shadow_runs`, `shadow_variances`,
  `app.run_shadow_reconcile`; `exam_results`, `app.compute_exam_results`; `ai_reports` (unique per school,
  kind, department and period). Applied with three hand amendments while uncommitted (unique index over
  `COALESCE(department, '')` instead of a table constraint; `COALESCE(receipt_no, 'payment:' || id)` as
  the variance reference for unnumbered payments; explicit casts in the worker's alert insert).
- Permissions: `fees.shadow.view` / `fees.shadow.manage`, `platform.service_key.manage` (MFA),
  `insights.report.view` / `insights.report.run`. Grants: administrators all; accountant shadow view and
  manage and report view; auditor and coordinator view. `POST /shadow/feeds/ingest` is the one new public
  route (allow-listed in the permission-coverage spec; authenticated by the key).

## 4. Deviations and decisions

- The VAPT retest lives in its own spec (`pentest-fees.e2e-spec.ts`) rather than a section of
  `pentest.e2e-spec.ts`, so it can run alone with the performance probe.
- The AI reports keep facts and narrative apart (`facts` JSON with the query per fact; `citations` checked
  against them); an unknown citation from the provider is dropped and counted, never shown as a fact.
- The service key is a generic credential (RFID device-key pattern) with scopes, so later feeds (transport
  GPS, biometric) reuse it.
- Promotion proposals do not write; they pre-fill the Sprint 7 register, keeping one place where the year
  rollover is decided and applied.
