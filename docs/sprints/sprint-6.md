## 2. Data model and permissions

- Migration `0016_sprint6_academics_setup.sql`: 7 tables, 5 enums, 2 routines, 1 trigger, all tenant tables under forced row-level security.
- Permissions: `academics.subject.view|manage`, `academics.teacher_assignment.view|manage`, `academics.timetable.view|manage`, `people.import.run`. Templates: Group Admin, School Admin and Academic Coordinator manage; Class Teacher, Subject Teacher and Auditor view. The demo Front Office role can view and run imports.
- Scopes: `academics.teacher_assignment.view` and `academics.timetable.view` honour `class_section` scopes, so a class teacher lists and reads only their own sections (`scope-denied` elsewhere).

## 4. Decisions

- Assignments, not manual grants, are the intended way to give teachers access (ADR-004). Manual role grants still work and are never touched by the sync (only rows with reason `teacher assignment sync` are revoked).
- Ended assignments stay as history (`valid_to`); uniqueness applies to live rows only.
- The import keeps the parsed rows in the `imports` row so commit replays exactly what was validated; a file with any rejected row must be fixed and re-uploaded (no partial imports).
- The timetable is stored per section and weekday against a school-wide period grid; campus-specific periods are supported by `campus_id` but the admin screen edits the school-wide grid only.
