## 3. Decisions

- **Hostel is a ledger, not a module**; the same procedures serve it.
- **MFA on the approval, through the permission catalogue** (`requires_mfa`) rather than a per-route flag, so the rule is visible under Access → Roles.
- **Bounce charges are demand rows**, so they show in dues, ageing and the dashboards.
- **Profile changes after generation are approvals**; the initial profile stays a direct edit.
- **The assistant answers only through the catalogue** (ADR-012); the mock router has a specificity threshold so a single generic word ("class", "this month") never picks a query.

## 5. What the tests found before release

- **Nested tenant transactions return nothing.** `reconcileNow` and `createType` re-entered `db.tenant` from inside a transaction and answered an empty body; both now read through the open client. Worth a lint rule later.
- **`app.setting()` is NULL for keys never set**; the bounce charge now falls back to the catalogue default (₹500) like the settings service does.
- **The mock router needed a specificity threshold**: "class" or "this month" alone picked a query; keywords are now scored by length and a score below 6 refuses.
- **Coordinators legitimately see fee entries** (they hold `insights.dashboard.view` since Sprint 12), so the permission test uses misc receipts, which they cannot run.

Known gaps carried forward: assistant for teachers and parents (Sprint 15), evaluation set of 200 questions (Sprint 16), family receipt PDFs still need the workers running.
