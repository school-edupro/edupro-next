# Threat model: people and daily academics (Sprint 7, S7-10)

Scope: the people module (students, guardians, employees, documents, imports, transfer certificates,
withdrawals, promotions) and daily academics (homework, classwork, assignments with files, notices,
holidays, almanac, gallery, document templates). Method: STRIDE over the data flows below; controls are
the ones implemented in Sprints 4 to 7 and proven by the e2e suites named in each row.

## 1. Data flows

1. Teacher app → API → `daily_work` (+ files through the file service) → parent app.
2. Admin → API → `notices` with audience and targets → parent and teacher apps.
3. Admin → API → `document_templates` → export worker (Chromium) → PDF in object storage → download URL.
4. Admin → API → `transfer_certificates`, `student_withdrawals`, `promotion_decisions` → enrolments and status changes.
5. Browser → API file service → local or S3 storage (signed upload URL, HMAC or pre-signed).

## 2. Threats and controls

| Id  | Threat (STRIDE)                                                                                  | Control                                                                                                                                                                                                                               | Evidence                                                                                |
| --- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| T1  | A teacher posts homework, or reads it, for a section they do not teach (Elevation)               | `academics.daily_work.post` is scope-checked against `class_section` scopes that are derived from live teacher assignments (Sprint 6 sync); reads apply the same scopes                                                               | `daily-academics.e2e-spec` "posts homework for their section only" (403 `scope-denied`) |
| T2  | A guardian reads another child's homework or a notice for another class (Information disclosure) | Family viewers are resolved from `guardians.user_id` / `students.user_id` to their own children; lists and detail reads are filtered by the children's sections, targets and audience; requests naming another section answer 403     | "a parent reads their child's section only", "notices reach the audience and targets"   |
| T3  | Draft notices or staff circulars leak to families (Information disclosure)                       | Only `published_at` rows within their publish window are visible without the manage permission; audience `employees` never reaches family viewers; almanac and gallery follow the same audience rule                                  | notices, calendar and gallery tests                                                     |
| T4  | Malicious upload: HTML, scripts, executables, oversized bodies (Tampering, DoS)                  | Content-type allow-list (images, PDF, CSV, XLSX, DOCX), size classes, object keys generated by the server (never the client name), HMAC-signed local tokens with expiry, per-classification limits; scanner hook                      | `files.e2e-spec` and "file uploads refuse unknown content types"                        |
| T5  | Attaching another school's file, or a file that never finished uploading (Tampering)             | Attachments are re-read through the file service under row-level security (foreign ids are not found) and must be `ready`                                                                                                             | "a pending upload cannot be attached" (409 `file.not_ready`); foreign file 404          |
| T6  | Stored XSS through document templates or template data (Tampering)                               | Placeholder values are always HTML-escaped by the engine; the engine evaluates no code; templates are edited only with `platform.template.manage` (admin roles) and rendered in a headless Chromium with no network access to the app | "placeholders are escaped" in the templates test; unit tests of the engine              |
| T7  | Forged or duplicate transfer certificates (Repudiation, Tampering)                               | Numbering comes from a row-locked per-school sequence (`app.next_tc_no`); one issued TC per student; every issue, render and cancel is audited with the actor; the student snapshot is frozen at issue time                           | TC test (`TC/2026-27/0001`, 409 `tc.already_issued`)                                    |
| T8  | A withdrawal completed with dues outstanding (Tampering)                                         | Completion runs in `app.complete_withdrawal`, which refuses unless every department clearance is `cleared`; clearances need `people.withdrawal.clear`; completion deactivates the student login                                       | withdrawal test (409 `withdrawal.clearance_pending`)                                    |
| T9  | Promotion into the wrong year or section (Tampering)                                             | Decisions validate the target section against the target year; `app.apply_promotion` re-uses `app.enrol_student` (year open, section belongs to year, student active) and is idempotent                                               | promotions test (409 `promotion.section_not_in_year`, second apply is a no-op)          |
| T10 | Cross-tenant reads of any Sprint 7 table (Information disclosure)                                | Every new table is under forced row-level security through `app.apply_tenant_rls`; the outsider tests answer 404                                                                                                                      | e2e outsider checks; `rls.test.ts`                                                      |
| T11 | Denial of service through large CSV or attachments                                               | CSV limited to 2 MB, 10 attachments per post, 100 images per album, body size limits per content type in Fastify                                                                                                                      | DTO limits                                                                              |

## 3. Residual risks and follow-ups

- Notices and daily work are not yet pushed to devices; when notifications arrive (Sprint 10) the same audience resolver must drive recipients.
- Gallery images are served through signed download URLs with a short expiry; a public CDN in front of object storage is a deployment decision.
- Template editing is limited to administrators; a school-level reviewer flow for templates is a later refinement.
- File scanning is a hook; a real antivirus scanner is wired in the deployment (ClamAV or the provider's service).
