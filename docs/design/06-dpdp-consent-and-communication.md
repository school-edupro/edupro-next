# DPDP consent and communication (Sprint 10)

Scope: message requests and approval (`apps/api/src/modules/comms/requests.service.ts`), consent purposes and
records (`consents.service.ts`), delivery receipts (`delivery.service.ts`), parent engagement
(`modules/engagement`), bus readers and biometric punches (`modules/attendance`). Builds on threat models 03 to 05.

## 1. Consent model (Digital Personal Data Protection Act, 2023)

| Element      | Implementation                                                                                                                                                                                                                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Purposes     | `consent_purposes` per school, versioned wording (`version`), optional channel. Defaults: SMS, WhatsApp and email updates; photographs in the gallery; bus alerts and location sharing.                                                                                                                  |
| Records      | `consents` is append-only: every grant or withdrawal is a new row with source (`parent_app`, `office`, `import`, `seed`), the purpose version, who recorded it and when. `app.consent_status()` reads the latest.                                                                                        |
| Self-service | Parents grant or withdraw in the parent app (**Profile → Your consents**); the office records signed forms (**Communication → Consent**) with a note. Required purposes cannot be withdrawn in the app.                                                                                                  |
| Effect       | `general` message requests skip recipients whose consent for `comms.<channel>` is withdrawn (recorded as `consent_withdrawn`, visible on the request). `service` messages (fees, attendance, safety) are sent regardless, as notices necessary for the service. Bus alerts respect `transport.tracking`. |
| Evidence     | Every skip is kept per recipient; consent history is exportable per person from the office view; audit rows record who recorded what.                                                                                                                                                                    |
| Not covered  | Data principal rights requests (access, erasure) beyond the profile change flow; a retention schedule for `comms_messages` bodies (carried to the DPDP work in Sprint 11).                                                                                                                               |

## 2. Threats and mitigations

| Id  | Threat (STRIDE)                                          | Mitigation                                                                                                                                                                                                                                                       | Evidence                                                    |
| --- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| C1  | Mass message sent without oversight (E)                  | Every request runs through the `message_approval` workflow (Principal level); dispatch happens only inside the approving transaction; requesters can cancel until dispatch.                                                                                      | `communication.e2e-spec.ts` approval and rejection cases    |
| C2  | Message to people who opted out (R, DPDP)                | Consent applied at dispatch for general messages; recipients without an address or duplicates skipped and recorded.                                                                                                                                              | preview and dispatch cases                                  |
| C3  | Recipient addresses leaking through screens (I)          | Request views mask mobiles and emails (`******0001`); the full delivery log stays behind `comms.message.view`.                                                                                                                                                   | `mask()` in requests.service                                |
| C4  | Forged delivery receipt flipping message state (S, T)    | Shared `COMMS_WEBHOOK_TOKEN` compared in constant time (dev default refused in production); receipts are matched by provider message id through a SECURITY DEFINER lookup, stored once per (provider, receipt, status), and never downgrade a delivered message. | receipt cases: 401, applied, duplicate, unknown             |
| C5  | Templates with unregistered SMS content (compliance)     | Requests reference an active template; SMS templates carry DLT ids; push templates are refused for requests.                                                                                                                                                     | template check in `create`                                  |
| E1  | A family reading another family's queries or profile (I) | `ViewerService` limits families to their linked children on every read and write; staff detail reads are scoped by permission; internal notes are filtered for families.                                                                                         | `engagement.e2e-spec.ts` stranger 404, internal note hidden |
| E2  | Parents editing records directly (T)                     | Change requests carry an allow-list of fields, the old and new values, and apply only on staff approval with an audit row on the student or guardian.                                                                                                            | change request cases                                        |
| E3  | Staff seeing queries outside their sections (I)          | Query lists use class-section scopes for scoped roles (class teachers); unscoped roles (accountant, admins) see all.                                                                                                                                             | teacher B sees none                                         |
| D1  | Fake bus or punch device (S)                             | Per-device keys (sha256 stored, constant-time compare); the device kind decides which endpoint accepts it (`device-kind` 409 otherwise).                                                                                                                         | `devices.e2e-spec.ts` wrong key, wrong endpoint             |
| D2  | Replayed taps or punches (T)                             | Bus: same student and direction within 60 s is a duplicate. Punches: unique (device, id, time) plus a 60-second window.                                                                                                                                          | duplicate outcomes                                          |
| D3  | Location data of children (I)                            | Only the reader's position at the tap is stored; shown to the child's own guardians and staff with `attendance.bus.view`; alerts stop when `transport.tracking` is withdrawn.                                                                                    | consent withdrawn case                                      |

## 3. Residual risks

- Real SMS/WhatsApp providers and their receipt formats are not wired; the receipt endpoint accepts a normalised JSON shape that an adapter will map to.
- Consent wording versions are not yet shown to parents when the wording changes (planned with the DPDP notice work in Sprint 11).
- Punch devices report local time; a skewed clock shifts first-in and last-out. Server receive time is stored alongside.
