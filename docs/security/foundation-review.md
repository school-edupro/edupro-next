## 2. Controls verified

- Authentication: One Auth tokens verified against JWKS with issuer and audience; compat and impersonation tokens are HS256 with distinct secrets and issuers; sessions are encrypted HttpOnly cookies (`ADR-007`).
- Tenancy: every tenant table has forced row-level security; the application role cannot bypass it (start-up assertion); cross-tenant routines are SECURITY DEFINER with narrow surfaces and are listed in ADR-006 and ADR-009.
- Authorisation: deny by default; every handler declares a permission or is on the reviewed public allow-list (CI test); MFA freshness enforced from `auth_time`; segregation of duties at grant time and at request time; class-section scopes applied in list, detail, search and exports.
- Audit: append-only partitioned log, rows written inside service transactions, masking of sensitive fields, impersonation recorded on every row, query and export (MFA) endpoints.
- Data protection: PII redaction in logs and worker logs; staging anonymisation script with a guard on the database name; backups with checksums and a restore drill.
- Supply chain: `pnpm audit` at high, gitleaks secret scan, pinned Fastify, Playwright images for the workers.
- Runtime: Helmet, CORS allow-list, rate limiting, body-size limits per content type, problem-details responses without stack traces, security event counters and alerts.

## 3. Residual risks for the M1 gate

- Staging and production environments are defined in Terraform but have not been applied; DAST runs against the CI-hosted stack only.
- The current mobile apps have not yet signed in against the compatibility API (needs staging and an app build).
- Column-level encryption for outbox payloads and a nonce cache for the handshake are scheduled for Sprint 6.
